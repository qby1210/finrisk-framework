# FinRisk Query 4.0 技术报告

> 文档版本：1.0  
> 对应系统版本：Query Analysis Schema 4.0  
> 编写日期：2026-08-26  
> 报告范围：当前仓库中“用户 Query 输入—风险判断—相似案例—Web 展示”的已实现版本

## 1. 摘要

FinRisk Query 4.0 面向保险营销与经营合规场景，接收用户直接输入的文本，或 PDF、图片、
TXT、Markdown、DOCX 文件，完成多模态内容抽取、六类场景识别、可逆切句、逐句风险判断、
标签对齐的相似案例检索和文档级风险聚合，并通过 API 与浅色 WebUI 输出可解释结果。

系统采用“本地优先、模型复核、检索后置”的架构：

1. 能由高精度本地规则确定的场景和风险直接输出，减少模型调用；
2. 中低置信内容由大模型进行动态批量语义复核；
3. 风险判断阶段不注入历史案例，避免案例相似度反向污染风险结论；
4. 仅对达到检索阈值且已有风险标签的句子查找案例；
5. 案例召回采用 BM25 与本地 TF-IDF 余弦双路召回、RRF 融合和确定性轻量重排；
6. 所有句子保留全文偏移、页码、坐标与上下文，可回到原始材料高亮证据。

在 data/raw/query/query_test_set_60.json 的完整模型评测中，60 条样本全部成功处理，
场景分类准确率为 98.33%，风险二分类 Precision、Recall、F1 均为 100%，多标签
Micro-F1 为 77.43%，平均单条处理时间为 9.05 秒，P95 为 15.27 秒。该结果说明当前版本
已经具备比赛演示所需的完整闭环，同时多标签边界、语义向量能力和全仓静态类型债务仍有
进一步优化空间。

## 2. 项目目标、原则与边界

### 2.1 核心目标

系统解决的不是单一关键词检索，而是以下连续问题：

- 输入可能是短文本，也可能是带原生文本层或扫描页的复杂文档；
- 同一句表达在海报、直播、产品详情、说明会、培训电销、处罚事实中的风险含义不同；
- 27 个风险标签存在语义重复、上下位和包含关系，标签结果允许多选；
- 风险是否成立必须先由文本本身判断，历史案例只能用于解释和类案参考；
- 比赛展示需要给出“为什么判断、原文在哪里、相似案例是什么”，而不是只给总分。

### 2.2 设计原则

| 原则 | 当前实现 |
| --- | --- |
| 本地优先 | 场景高置信规则直出；逐句高置信强风险信号直出 |
| 模型按需 | 规则不确定时才调用大模型，短材料整篇批量，长材料分批并发 |
| 风险与检索解耦 | 案例相似度不进入风险分，风险结论先于案例检索产生 |
| 标签约束 | 大模型只能从固定 27 标签中选择，未知标签在契约校验后丢弃 |
| 可解释 | 输出规则证据、模型理由、原文证据短语、定位和检索分解分数 |
| 可回溯 | 文件哈希、抽取方式、OCR 置信度、页码、文本块和全文偏移均保留 |
| 可降级 | 风险复核批次失败时回退本地结果并返回 warning，不中断整份材料 |
| 确定性排序 | 检索排序由固定公式完成，同一数据和 Query 下可复现 |

### 2.3 当前边界

- 当前系统用于合规辅助筛查，不替代最终人工合规意见或法律结论。
- 当前“向量召回”是本地 TF-IDF 稀疏向量余弦相似度，不是神经网络语义嵌入。
- 案例库、案例录入和案例查看能力沿用现有实现，本次 Query 4.0 未重写案例数据。
- 大模型只参与场景兜底和风险语义复核，不参与最终案例重排。
- 当前报告只描述已经落入代码并通过验证的能力，不把后续规划写成现状。

## 3. 系统总体架构

### 3.1 端到端处理链

~~~text
用户文本/文件
    │
    ▼
统一输入与多模态抽取
    │  文本、页、块、词、坐标、OCR置信度、SHA-256
    ▼
六类场景分类
    │  本地规则候选 → 高置信直出 / 低置信LLM唯一分类
    ▼
可逆切句与来源映射
    │  sentence_id、全文offset、页码、区域、前后文
    ▼
逐句两阶段本地风险初判
    │  Stage 1强组合规则 + Stage 2场景加权关键词
    ▼
动态LLM语义复核
    │  高置信本地直出；其余按字符预算批量复核
    ▼
风险分融合、等级与标签集合
    │
    ├── risk_score < 0.40：不检索
    │
    └── risk_score >= 0.40 且标签非空
            │
            ▼
       标签过滤后的混合案例检索
       BM25 + TF-IDF cosine → case级RRF → 本地轻量重排
            │
            ▼
文档整体风险聚合与Top案例去重
    │
    ▼
API 4.0 / 浅色WebUI
原文高亮、逐句结果、相似案例、整体结论
~~~

## 4. 输入、抽取与可回溯定位

### 4.1 支持的输入

| 输入类型 | 主要处理方式 | 保留信息 |
| --- | --- | --- |
| 原生文本 | 直接标准化 | 文本、字符偏移、输入类型 |
| PDF | 原生文本层优先；扫描页使用 RapidOCR | 页码、块/词、坐标、置信度、抽取方式 |
| 图片 | RapidOCR | 页面、文本块、词、归一化四边形、OCR 置信度 |
| TXT / Markdown | 文本解码 | 文本与全文偏移 |
| DOCX | 文档段落抽取 | 段落文本和统一来源结构 |

抽取层输出不仅包含 normalized_text，还包含媒体类型、SHA-256、页数、OCR 页数、
文本块数、词数、抽取质量分和 warning。这样可在结果异常时区分“原文无风险”和
“抽取质量不足”。

### 4.2 PDF 与图片处理策略

PDF 先尝试读取原生文本层。对于没有可用文本层的扫描页，或图片输入，调用 RapidOCR。
坐标统一存储为页面归一化四边形，避免前端展示依赖原图像素尺寸。每个来源区域可保存：

- page_number：从 1 开始的页码；
- block_id 与 word_ids：OCR 或文本层中的最小可追踪单元；
- text：该区域对应文本；
- document_start_offset / document_end_offset：在全文中的字符范围；
- polygon：四个归一化坐标点；
- confidence：OCR 置信度；
- extraction_method：native、ocr 等抽取来源。

### 4.3 文件身份与质量控制

文件 SHA-256 用于标识同一输入，便于排查重复提交和抽取差异。抽取质量分、OCR 页数和
warning 会随 API 返回。文件过大返回 413；文件字段或抽取失败返回 422。上传过程使用
受控临时文件，完成处理后不把用户 Query 写入案例数据目录。

## 5. 六类场景分类

### 5.1 场景体系

| 编码 | 场景 | 典型信号 |
| --- | --- | --- |
| ST1_poster_sms_social | 海报、短信、朋友圈短文案 | 扫码、限时、退订、社交行动号召 |
| ST2_live_short_video | 直播、短视频、口播话术 | 主播、镜头、直播间、小黄车 |
| ST3_product_intro_detail | 产品介绍、详情页 | 产品要素、期限、费用、申购赎回、风险等级 |
| ST4_meeting_material | 产品说明会、客户活动材料 | 议程、主持、来宾、会议时间地点 |
| ST5_training_telemarketing_callback | 培训、电销、回访话术 | 坐席客户对话、异议处理、标准应答 |
| ST6_penalty_backend_fact | 处罚文书、后台业务事实 | 处罚决定、经查、系统日志、业务台账 |

场景描述材料用途，不等同于风险标签。一个 ST4 材料不因为“说明会”三个字就自动判为
违规；场景仅影响后续本地信号权重和渠道类标签的解释。

### 5.2 规则候选计算

规则分类器对六类分别累计显式载体词、结构词和文件形态信号。输出全部候选的：

- scene；
- score；
- confidence = 当前场景分 / 六类总分；
- evidence。

本地高置信直出必须同时满足：

~~~text
Top1 score >= 6.0
Top1 score - Top2 score >= 2.5
Top1 confidence >= 0.65
~~~

否则调用统一大模型，根据材料主要用途从六类中选出唯一场景。大模型接收规则候选作为
可质疑参考，输出 scene、confidence、reason，并由 Pydantic 校验。当前版本号为：

- taxonomy_version：query-scene-2.0；
- classifier_version：query-scene-rule-llm-3.0；
- rule_version：query-scene-rules-3.0。

### 5.3 长材料分类

场景分类以整份材料为单位。材料超过 24,000 字符时，模型输入保留头部与尾部，中间明确
标注省略，以控制延迟和 token 消耗，同时尽量保留文档标题、开头用途和末尾事实结论。

## 6. 可逆切句与上下文

切句器支持中文句末标点、空行、数字列表和社交平台项目符号。风险模块收到的每句对象
严格保持四字段：

| 字段 | 含义 |
| --- | --- |
| query_id | 本次材料标识 |
| sentence_id | 句子稳定标识 |
| scene | 文件级六类场景 |
| text | 当前句原文 |

定位信息不塞入风险输入对象，而通过相同 sentence_id 在 source_mappings 中一一关联，
包括全文起止偏移、页码、区域、前句和后句上下文。这个设计保证风险接口保持简洁，又能让
前端使用同一 offset 对原文做准确高亮。

## 7. 两阶段本地风险初判

### 7.1 为什么采用两阶段

“出现关键词就确定违规”会产生大量误报。例如“不得承诺收益”包含“承诺收益”，但实际
是合规约束；“历史收益不代表未来”包含收益词，却是风险提示。因此本地判断拆为：

1. Stage 1：高精度组合正则，识别明确违规语义；
2. Stage 2：关键词加权累积，识别较弱但可组合的风险信号。

### 7.2 Stage 1：强组合规则

强规则不是孤立单词，而是有距离约束的语义组合。例如：

- “虚构/伪造 + 发票/费用 + 列支/套取”；
- “业务员/代理人 + 代接/冒充 + 客户/投保人”；
- “未经备案/擅自 + 费率/条款”；
- “无资质机构/人员 + 销售/推介”；
- “返现/返佣/回扣 + 保费/佣金/现金”；
- “不告知/隐瞒 + 免责/等待期/退保/费用/风险”；
- “未经同意/违规获取联系方式 + 拨打/电销”。

每个强规则映射一个或多个风险标签。基础强度为 0.88，再乘场景适配系数：标签适合当前
场景时为 1.18，否则为 0.92，单信号最高 0.96。规则命中前 8 个字符内若存在“不、并非、
不得、严禁、禁止”等否定前缀，则该命中不作为风险证据。

### 7.3 Stage 2：场景加权关键词

关键词资产区分 curated 和 expansion 两种来源，权重由来源、优先级和场景共同决定。
当前基础权重为：

~~~text
curated  = 0.16 + 0.06 × min(priority, 3)
expansion = 0.06 + 0.025 × min(priority, 3)
strength = min(0.45, base × scene_factor)
scene_factor = 1.18（标签适合当前场景）或 0.92（其他场景）
~~~

多标签关键词会按标签数平方根分摊贡献，避免一个泛化词同时把许多标签推高。每句只取
最高的 6 个 Stage 2 信号参与分数累计，抑制长文本因关键词数量过多而膨胀。

### 7.4 Noisy-or 累积与限定语

两阶段都使用 noisy-or 聚合，而不是简单相加：

~~~text
noisy_or(s1...sn) = 1 - Π(1 - si)
local_score = 1 - (1 - stage1_score) × (1 - 0.78 × stage2_score)
~~~

该公式让多个独立弱证据逐步增强风险，但天然限制在 0 到 1。若句子出现“以合同为准、
不构成承诺、收益存在不确定、可能亏损、须经审核”等合规限定语，且没有 Stage 1 强规则，
Stage 2 分数按限定语数量衰减，最低保留 35%。

### 7.5 本地置信度与直出

strong_signal 在以下任一条件成立时为真：

- 至少命中一个 Stage 1 强规则；
- Stage 2 分数不低于 0.68，且至少有 3 个关键词信号。

流水线只有在 strong_signal 为真且 local_confidence 不低于 0.90 时才跳过风险 LLM
复核。其余句子进入中低置信复核集合。由此既保留强规则速度，也避免弱关键词直接定性。

## 8. 27 类标签与模型语义复核

### 8.1 标签集合

当前固定标签如下，标签之间不要求互斥：

| 维度 | 标签 |
| --- | --- |
| 误导与宣传 | 欺骗投保人、销售误导、夸大收益、虚假宣传、绝对化表述 |
| 收益与风险披露 | 承诺收益、保证收益、弱化风险提示、隐瞒重要信息、虚构收益率 |
| 利益诱导 | 合同外利益、赠送利益、回扣返佣、诱导投保 |
| 渠道与材料 | 产品说明会违规、培训材料违规、回访违规、电销违规 |
| 比较与特殊宣称 | 不当比较、贬低竞品、避债避税 |
| 后台经营事实 | 虚列费用套取资金、代理人管理不到位、委托无资质机构销售、未按规定使用费率条款、客户信息不真实 |
| 兜底 | 其他 |

模型提示词明确说明：标签存在语义重复、上下位和包含关系，只要语义明确相关，可以同时
输出。例如“保证年化收益”可能同时关联承诺收益、保证收益、夸大收益、虚构收益率和
销售误导，但不能仅因词面相似而无证据堆砌。

### 8.2 动态批量策略

风险模型调用使用以下策略：

| 条件 | 处理 |
| --- | --- |
| 高置信强本地信号 | 本地直出，不调用模型 |
| 整篇句子总长度不超过 6,000 字符 | 全文句子放入一个批次作为上下文，只输出待复核句 |
| 长文 | 只对待复核句按 6,000 字符和最多 12 句切批 |
| 多批次 | 最大并发 2 |
| 批次失败 | 回退本地结果，warning 中记录错误 |

短 Query 将全部句子一起提供给模型，可处理跨句否定、前后限定和标题语境，同时只要求
返回 review_ids，避免重复输出高置信本地句。长 Query 的每个待审句还携带前后最多
400 字符上下文。

### 8.3 模型输入和输出约束

模型输入包含：

- sentence_id、scene、text；
- context_before、context_after；
- local_stage1_score、local_stage2_score；
- 本地候选标签和最多 5 条本地证据；
- 27 个允许标签及其定义。

模型输入明确不包含案例原文、相似案例分数或处罚结论。输出必须为 JSON，包括：

~~~json
{
  "items": [
    {
      "sentence_id": "S001",
      "risk_score": 0.86,
      "risk_labels": ["承诺收益", "保证收益"],
      "evidence": ["保证年化收益"],
      "reasoning": "对未来收益作出确定性保证"
    }
  ]
}
~~~

每批输出由 Pydantic 校验：风险分限制在 0 到 1，单句最多 10 个标签、5 条证据，理由
最长 500 字；不在固定体系中的标签被丢弃。模型 temperature 为 0，以提升可复现性。

## 9. 风险融合、分级和标签解析

### 9.1 风险分融合

风险分只融合本地判断和 LLM 语义复核，不使用案例相似度：

~~~text
无LLM结果：
    final = local

强本地信号且本地置信度 >= 0.85：
    final = 0.55 × local + 0.45 × llm

其他已复核句：
    final = 0.25 × local + 0.75 × llm
~~~

如果 local 与 llm 的最高分都小于 0.20，最终分被限制在 0.19 以内，避免无风险内容因
加权误差跨过展示阈值。

### 9.2 五档风险等级

| 分数区间 | 等级 | 默认动作 |
| --- | --- | --- |
| 0.85–1.00 | 高风险 | 拦截并人工复审 |
| 0.60–0.85 | 中风险 | 标记并提示修改 |
| 0.40–0.60 | 疑似风险 | 建议人工复查 |
| 0.20–0.40 | 低风险 | 记录并观察 |
| 0–0.20 | 无明显风险 | 放行 |

### 9.3 最终标签集合

只有 final_score 不低于风险展示阈值 0.20 时才输出标签。标签候选按以下来源合并：

1. 经校验的 LLM 标签；
2. 本地分达到展示阈值或存在强信号时的规则标签；
3. 与场景和原文明确相关的渠道标签，例如说明会违规、回访违规、电销违规；
4. 标签关系表中的相关、上下位和包含标签扩展。

最终去重并限制为最多 10 个。这个策略适配比赛给出的非互斥 27 标签，但也直接导致
“完全匹配”指标比二分类指标更严格。

## 10. 风险门控后的相似案例检索

### 10.1 检索门控

默认只有同时满足以下条件的句子进入案例检索：

~~~text
final risk_score >= FINRISK_RETRIEVAL_RISK_THRESHOLD（默认0.40）
且 risk_labels 非空
~~~

低风险和无明显风险句不检索，避免无意义耗时和“看起来相似的案例”诱导用户误以为已
构成风险。每个入选句默认返回 Top 3 案例，检索并发上限为 4。

### 10.2 标签硬过滤

检索前移除兜底标签“其他”，案例候选必须满足：

~~~text
sentence.risk_labels ∩ case.risk_tags 非空
~~~

因此，文本相似但风险类别完全不一致的案例不会进入候选。返回结果还显式携带
matched_risk_tags，供前端展示标签对齐依据。

### 10.3 检索文档

索引继续使用现有案例库中的：

- case_chunk：案例原文 fact/evidence 等切片；
- case_expansion：案例的启用扩展表达。

同一检索单元可关联一个或多个案例。索引按案例库 revision 懒加载；案例库版本未变化时
复用内存索引，变化时在锁保护下重建。

### 10.4 双路召回

两路共用中文 unigram/bigram 分词和倒排表：

- BM25：强调词频、逆文档频率和文档长度归一化；
- TF-IDF cosine：将 Query 与检索单元表示为归一化稀疏向量，计算余弦相似度。

默认 Top 3 时，每路召回池大小为 max(120, top_k × 40)，即 120 个检索单元。命中聚合
到案例级：同案例最佳单元作为主要证据，其他命中以 12% 的分数增益提供支持。

### 10.5 RRF 融合

BM25 与向量通道分别得到案例排名。当前 RRF 参数 k = 60：

~~~text
rrf_raw(case) =
    1 / (60 + bm25_rank) +
    1 / (60 + vector_rank)

rrf_score = min(
    1,
    rrf_raw / (2 / 61)
)
~~~

某案例只在一路出现时，缺失通道贡献为 0。归一化后的 RRF 分便于和其他 0 到 1 特征
共同重排。

### 10.6 本地轻量重排

BM25 原始分先通过 1 - exp(-score / 18) 归一化。最终重排公式为：

~~~text
rerank =
    0.28 × rrf_score
  + 0.30 × normalized_bm25
  + 0.26 × vector_cosine
  + 0.11 × lexical_overlap
  + 0.05 × source_quality
~~~

其中 case_chunk 来源质量为 1.0，case_expansion 为 0.65；若 Query 与命中单元存在长度
不小于 6 的整段包含关系，再增加 0.06 短语命中奖励。结果最高截断为 1.0。排序依次按
rerank_score 降序、rrf_score 降序、case_id 升序，保证稳定性。

返回的 MatchedCase 同时保留 bm25_score、vector_score、rrf_score、rerank_score、
matched_text、matched_source 和 matched_unit_id，避免只给一个不可解释的总相似度。

## 11. 文档级风险聚合

整体风险分以最高风险句为主，第二至第四个风险句提供有限增益：

~~~text
maximum = max(sentence_scores)

若 maximum < 0.20：
    overall = maximum

否则：
    support = 第2至第4高分之和
    overall = min(
        1,
        maximum + (1 - maximum) × (1 - exp(-0.18 × support))
    )
~~~

该方法避免“很多无风险句”把整体分抬高，也避免简单平均稀释一条非常明确的高风险句。
文档级 risk_findings 按标签聚合最大分、命中句数和 sentence_ids；相似案例按 case_id
去重，保留每个案例最高分，最终输出 Top 5。

## 12. API 4.0 输出契约

### 12.1 Query 接口

### 12.2 顶层 QueryAnalysisResult

schema_version 固定为 4.0。主要字段包括：

| 字段 | 内容 |
| --- | --- |
| input / extraction | 输入元数据、抽取统计、哈希和质量 |
| classification | 六类场景、置信度、方法、证据和规则候选 |

### 12.3 逐句与整体字段

- final risk_score、risk_level、中文等级和 action；
- risk_labels、reasoning、method；
- local_score、local_confidence、llm_reviewed；
- retrieval_performed、evidence、matched_cases。

整体 QueryRiskSummary 包含：

- overall_score、overall_level、action；
- risk_labels、risk_findings、top_matched_cases；
- 展示阈值与检索阈值；
- 总句数、风险句数、最高句分；
- 是否使用模型、模型名称、模型复核句数、本地直出句数、检索句数；
- 降级或异常 warning。

### 12.4 错误与降级语义

| 状态 | 含义 |
| --- | --- |
| 413 | 上传文件超过限制 |
| 422 | 输入字段、文件格式或抽取结果不合法 |
| 502 | 需要的模型供应商调用失败 |
| 503 | 场景分类规则不确定，但未配置可用大模型 |

场景分类必须得到唯一结果，因此模型缺失时不能悄悄猜测；风险批次则允许逐批降级为本地
结果，并在 response warnings 中显式告知。

## 14. 工程效率设计

### 14.1 减少模型调用

- 场景满足三项阈值时规则直出；
- 风险高置信强信号句本地直出；
- 短文整篇一次复核，减少逐句网络往返；
- 长文按字符和句数双预算分批，批次最大并发 2；
- 只要求模型输出待复核句，其他句仅作为上下文。

在 60 条完整评测中，54 条材料实际使用过风险 LLM，说明测试集包含较多需要语义判断的
中低置信表达；明确强规则仍能在部分句子上直接节省调用。

### 14.2 控制检索成本

- 检索只处理分数不低于 0.40 且标签非空的句子；
- 每句 Top 3，双路各召回 120 个检索单元；
- BM25 和 TF-IDF 共用分词与倒排数据；
- 索引按案例库 revision 复用，不为每条 Query 重建；
- 多个待检索句通过线程卸载和最多 4 路并发执行。

评测前索引预热约 5.02 秒；预热后单条分析不会重复承担完整索引构建成本。

### 14.3 确定性与可测试性

- 本地规则、融合、门控、聚合和重排全部为确定性函数；
- LLM 请求 temperature 为 0，输出有严格 JSON 契约；
- 数据模型负责分数范围、列表长度和句子对应关系校验；
- 风险 LLM 失败可按批次回退，错误通过 warning 可观测；
- 检索排序使用 case_id 作为最终稳定排序键。

内容形态而不是传播载体。

- sentence_id 一一对应关系在顶层契约二次验证；

## 19. 当前限制与下一步建议

### 19.1 当前限制

1. **向量通道语义能力有限。** 当前 TF-IDF cosine 不需要模型下载且速度稳定，但对同义
   改写、跨句语义和低词面重合案例的召回能力弱于领域嵌入模型。
2. **多标签边界仍需校准。** 27 标签的重复与包含关系导致合理扩展标签和金标集合不总是
   一致，完全匹配率仍为 36.67%。
3. **场景载体词依赖。** 渠道标识缺失时，科普内容与产品详情可能混淆，QT-042 已体现。
4. **LLM 延迟与供应商可用性。** 完整模式平均约 9 秒，网络波动会影响现场响应。
5. **OCR 真实噪声覆盖有限。** 已验证图片上传链路，但仍需更多低清、旋转、多栏和复杂
   表格文档回归。
6. **静态类型技术债。** 全仓仍有 20 条既有 Mypy 问题，集中在处罚爬虫和案例仓库。

### 19.2 建议优先级

| 优先级 | 建议 | 预期收益 |
| --- | --- | --- |
| P0 | 固化比赛现场模型、超时、重试和预热脚本 | 降低演示环境不确定性 |
| P0 | 增加真实 OCR 与长文回归集 | 防止抽取误差在后续层放大 |
| P1 | 为 QT-042 类材料增加“传播载体优先”特征 | 提升六类分类稳定性 |
| P1 | 基于验证集校准标签关系与每标签阈值 | 提升多标签 F1 与完全匹配 |
| P1 | 引入可选的中文金融领域嵌入通道 | 提升低词面重合案例召回 |
| P2 | 补齐全仓 Mypy 与浏览器视觉回归 | 提升长期维护和界面稳定性 |

引入神经向量时应保持当前 BM25、标签硬过滤、RRF 和可解释分解字段，不应把新向量分数
直接用于风险定性。

## 20. 比赛演示建议

建议准备三类输入，按同一页面连续展示：

1. **短营销文案强风险**：展示本地强规则、多个相关标签、原文高亮与 Top 案例；
2. **带限定语的中等材料**：展示动态 LLM 复核如何避免“关键词即违规”；
3. **图片或扫描 PDF**：展示 RapidOCR、页码坐标、抽取质量和逐句定位。

讲解顺序建议固定为：

~~~text
输入与抽取可追踪
→ 六类场景为什么这样判断
→ 每句风险分、标签和证据
→ 只有达到0.40才检索
→ 案例标签必须对齐
→ 最后才聚合整篇结论
~~~

这条主线能清楚体现系统不是“让大模型直接给答案”，而是本地规则、语义复核、检索工程
和证据定位共同组成的可解释合规流水线。

## 21. 结论

FinRisk Query 4.0 已完成从多模态输入到整体结论的端到端改造，并保留原案例管理能力。
当前版本的关键价值在于：本地规则优先降低成本，动态批量模型补足语义，风险判断与案例
检索严格解耦，标签硬过滤保证类案方向一致，原文坐标和分解分数保证结果可解释。

60 条完整评测和 40 项自动化测试表明系统可以在本机稳定运行并用于比赛演示。后续优化
重点应放在真实数据扩充、多标签校准、可选领域语义向量和工程回归，而不是改变现有的
“先判断风险、后检索案例”基本架构。
