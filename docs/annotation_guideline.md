# Query 标注规范

## 1. 适用范围

本规范用于保险营销材料、销售话术、监管处罚事实的场景分类、风险二分类、27 类风险多标签及证据片段标注。测试集只能由人工复核后的样本组成；开发集和合成长尾集不得直接并入测试集。

## 2. 六类场景

| 场景 | 定义 | 关键判定依据 |
| --- | --- | --- |
| ST1 | 海报、短信、朋友圈、社交平台短文案 | 短、单向传播、行动号召 |
| ST2 | 直播、短视频、主播口播 | 主播、镜头、直播间、口播脚本 |
| ST3 | 产品介绍、详情页、产品说明内容 | 产品要素、责任、期限、费用、申赎 |
| ST4 | 产品说明会、客户答谢会、讲师材料 | 会议议程、主持、嘉宾、讲师备注 |
| ST5 | 内部培训、电销、回访、异议处理 | 坐席/客户对话、培训要求、回访流程 |
| ST6 | 监管处罚文书、后台业务事实 | 经查、处罚决定、系统/财务/审计记录 |

若用户能确认材料载体，应记录为用户指定场景；否则按文本证据分类。ST4/ST5 的“材料载体”前缀只提供可观测上下文，本身不等于违规结论。

## 3. 风险标注

- `overall_risk=有风险`：文本中至少存在一项明确违规陈述、执行要求或已发生事实。
- `overall_risk=无风险`：仅为合规提示、否定违规做法、正常流程或不包含风险事实。
- 风险标签必须来自 `risk_type_dictionary.csv` 的 27 类词表，不创建临时同义标签。
- 同一句可多标签；仅标注原文能够支持的标签，不因上下位关系机械扩展全部标签。
- “其他”只用于确有风险但无法归入其余 26 类的情况，不能作为不确定标签。
- 载体类标签（产品说明会违规、培训材料违规、电销违规、回访违规）只有在对应载体中出现风险内容时标注。

## 4. 证据与理由

- `evidence` 必须是 Query 原文中的连续短语，不写模型解释。
- `rationale` 说明“原文事实—标签”的对应关系，避免引用训练案例作为判定依据。
- 否定句、引用监管要求、反面培训示例必须结合上下文判断，不可只按关键词标风险。
- OCR 错字影响判断时，保留原文并在复核意见中记录，不静默改写原文。

## 5. 数据划分与泄漏控制

- 测试集：`query_test_set_160.json`，人工复核后冻结，只用于最终评测。
- 开发集：`query_dev_set.json`，由已有检索训练 Query 规范化生成，允许调试；不得反向修改测试答案。
- 长尾增强集：`query_long_tail_enhancement.json`，全部为合成且待人工复核，只能在复核后用于训练。
- 构建脚本对开发集与测试集执行去材料前缀、去空白后的完全匹配排除。
- 队友制作的人工检索测试集应单独保存，不从 `relevant_cases` 自动复制成金标准。

## 6. 人工复核状态

- `confirmed`：确认模型场景和标签。
- `corrected`：填写修正场景和/或修正标签，并说明原因。
- `rejected`：证据不足、抽取失败或需重新审查。

Web 复核记录写入 `data/processed/reviews/query_reviews.jsonl`，包含 Query ID、输入哈希、原标签、修正标签、审核人和 UTC 时间，作为可追溯留痕。
