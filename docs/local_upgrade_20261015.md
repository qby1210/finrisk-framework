# 2026-10-15 本地改进说明

本轮对应秦负责的前端与 Query 上下文工作，并将全项目模型调用迁移到 Pi Agent。
同步包和分工截图用于核对接入边界；包内脚本、示例与审核草案没有作为生产数据执行或导入。
本说明记录本地开发与验证结果；本次源码同步 GitHub 不包含网站部署更新。

## 运行

运行环境为 Python 3.11+、Node.js 22.19+ 和 npm。本机已安装 Node.js 24.14。
安装脚本已补齐 Pi 依赖安装；现有虚拟环境可以直接执行：

```powershell
npm ci --prefix agent_runtime --ignore-scripts --cache agent_runtime/.cache/npm
.\.venv\Scripts\python.exe -X utf8 scripts/run_web.py --port 8015
```

本地预览为 `http://127.0.0.1:8015`。默认 `start.bat` / `start.ps1` 仍使用 8000 端口。
`.env` 中原有密钥保留在本地，模板不包含真实密钥。未配置模型时仍可使用本地规则，结果会
明确说明语义复核缺失。后端会在启动时预热 Pi 工作进程；预热不请求供应商，不消耗模型额度。

## Pi 接入及后续循环入口

原有 `llm/client.py` 中的 HTTP 模型请求已替换为常驻 Node 工作进程。场景分类、风险语义复核
和案例抽取共用这一入口：

```text
Python 业务服务
  → PiAgentLLMClient（并发门控、请求编号、取消和重试）
  → agent_runtime/worker.mjs（JSONL 通信）
  → Pi Agent / pi-ai（会话、工具执行、供应商协议）
  → DeepSeek
  → 结构化提交与业务契约校验
```

依赖固定为 `@earendil-works/pi-agent-core@1.2.0`、`@earendil-works/pi-ai@1.2.0`，并保留
`package-lock.json`。Pi 原 `badlogic/pi-mono` 仓库现跳转到
[earendil-works/pi](https://github.com/earendil-works/pi)。

`agent_runtime/runtime.mjs` 的工具列表与 `validateResult` 是后续接入核对逻辑的位置：

- `read_review_context` 只读取本次请求已提供的目标句、角色、上下文及位置。
- `submit_result` 提交 JSON。风险任务会校验目标句覆盖、标签字典、分数、理由和逐字引文；
  校验失败反馈为工具错误，由同一个 Agent 在剩余预算内修正。
- `finishTurn` 在成功提交后停止；未提交有效结果时最多执行 `FINRISK_AGENT_MAX_TURNS`
  轮，默认 4 轮，可配置 1–8。另有请求超时、取消与瞬时错误重试。
- 未注册文件、Shell 或写库工具。新增风险核对工具时应保持输入、证据和业务校验边界，
  先读取证据，再比较，再提交；不要在 Python 服务中另开 HTTP 模型调用通路。

每次成功语义复核将运行时版本、轮数、工具次数和事件类型写入 `risk_summary.agent_runs`。
这份执行记录不包含提示词、工具参数、原文或密钥。界面在“处理信息与判断来源”中展示统计。
`/api/health` 增加 Agent 依赖、工作进程和启动警告状态。

## DeepSeek 模型名称

2026-10-15 核查官方文档，推荐调用名为 `deepseek-flash`，对应 DeepSeek-V4.1-Flash。
旧 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍接受请求，但会转到 V4.1 Flash。
默认值和 `.env.example` 已更新；官方 DeepSeek 地址上的旧配置会自动映射为新名称。
自定义代理地址上的模型 ID 原样保留，避免改坏代理自身的命名。

来源：[DeepSeek Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)。
真实调用已成功返回 `deepseek-flash` 的结构化结果及 Pi 工具执行记录。

## 上下文与原文位置

旧版本已为部分模型复核提供相邻句片段，但本地高置信直出和检索仍主要使用孤立单句，缺少
显式说话人和作用域。此次保留原四字段 `RiskQuerySentence`，新增 `sentence_contexts` 侧表，
由 Query、Risk、检索和前端共同使用。原句文本、sentence_id、页码和全文偏移继续保留。

- 对话换行可形成句子边界，识别客户、顾问、坐席、讲师以及 Q/A 等显式角色，同段后续句可继承角色。
- 每句默认选择同作用域内前后各两句，邻句总预算为 1600 字；不会拼接不同段落和显式产品切换。
- 保存提问、否定、禁止性要求、反面话术等立场，短肯定回答会关联前问。
- 上下文敏感句会进入语义复核，不因孤立句的强词命中直接跳过；模型缺失或失败时标明仍需复核。
- 模型引文必须能在本句作用域的原文中逐字找到，并保存可回引的全文偏移；虚构引文会被拒绝。
- 超出上下文预算会保留警告；即使取得语义输出，仍保留补充完整上下文的复核状态。
- 案例检索以目标句为主，补充同作用域原文，不把相邻独立句的风险或其他产品的条件移植过来。

当前作用域和立场识别属于明确标记与有限规则，不能替代完整的金融行为分析。复杂指代、
含混引用及未标记产品需要结合完整原文复核。相关业务规则位于 `src/risk/context.py`，
上下文构造位于 `src/query/context.py`。

## 2026-10-15 原文高亮与语句边界回修

修复了原文高亮与逐句结果不一致的三个问题：Python 偏移按 Unicode 码点计数，而旧浏览器
代码用 UTF-16 下标截取，遇到 emoji、扩展汉字等字符会错位；旧选中样式会将无风险句也
染成红色；筛选隐藏了对应卡片时，点击原文无法找到逐句结果。还为静态资源加入版本号，
避免浏览器继续执行缓存中的旧脚本。

当前做法：

- 原文位置统一为 Unicode 码点的左闭右开区间。接口显式返回 `source_offset_unit` 和
  `segmentation_version`；浏览器从同一份位置表和 `sentence_id` 渲染全文与逐句判断。
  提交文字不再删除首尾空白，字数统计也使用同一字符单位。
- 切分按完整表达、明确说话轮次、空段与列表进行，保留 OCR 软换行。小数、网址、列表
  编号不按句号误拆；引号、括号及嵌套引用内部的标点留在完整表达中。同一行的新说话人
  可以另起一段，但引用内部的角色标签不被误当成新的对话轮次。
- 风险底色始终沿用该句自己的最终风险等级；蓝框只表示当前判断；蓝色下划线表示当前
  点击的证据，邻句证据另加虚线框。选中、悬停和引用均不会改变风险底色。
- 每张卡片的 S 编号可回到本句原文。上下文及判断依据可回到对应句或精确短语，并保留
  证据所属的判断。例如 S02 回答可引用 S01 客户问题，S01 继续保持自身的无明显风险等级。
  原文跳转遇到筛选隐藏卡片时，会自动切换为全部语句。
- 后端校验目标句、上下文、风险判断和证据的原文绑定，拒绝越界、重叠、遗漏及文字
  不一致；前端再校验一次。定位校验失败时显示完整原文及提示，避免把颜色落到另一句话。
  同一引文重复出现时，优先绑定当前目标句，避免跳到前一个相同表达。

最终运行 `verify.ps1`：**97 项 Python 测试、12 项前端原文映射测试、9 项 Pi Agent 测试**
全部通过，Ruff、Mypy、JavaScript 语法和 7,628 条原知识库完整性检查通过。Windows 和
Linux 验证脚本均包含新的前端映射测试；交付检查包含 `source-map.js`。

浏览器使用真实本地接口核对了带 emoji、首尾空格、问答承诺与含句号反面引用的材料：

证据可精确定位“是的，可以这样理解。”；邻句引用保持自己的风险等级；筛选隐藏语句后
仍可从原文定位。桌面与 390px 窄屏均无横向溢出。
